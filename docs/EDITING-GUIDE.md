# Clickdummy Editing Guide

The clickdummy is optimized for direct UI/UX editing without hiding product markup in JavaScript.

## 1. Global or page-specific?

Before changing something, decide whether the change should affect every page.

### Global

Edit a partial once:

- Header structure/classes → `partials/workspace-header.html`
- Footer → `partials/footer.html`
- Sidebar → `partials/sidebar.html`
- Navigation → `partials/navigation.html`
- Brand/logo → `partials/brand.html`
- User chrome → `partials/user.html`
- Mobile navigation → `partials/mobile-nav.html`
- Profile modal → `partials/profile-modal.html`

### Page-specific

Edit the page itself:

- `index.html`
- `kunden.html`
- `websites.html`
- `search-seo.html`
- `ads.html`
- `ai-visibility.html`
- `prompt-center.html`
- `entwicklung.html`
- `einstellungen.html`

The entire `view-content` area remains direct HTML.

## 2. Header workflow

Every page contains one readable include:

```html
<!-- @include partials/workspace-header.html {"title":"Kunden","description":"Welche Kunden betreue ich?"} -->
```

To change the header layout, element order or UIkit classes globally, edit:

`partials/workspace-header.html`

To change only a page title or description, edit only the values in that page's include line.

## 3. Navigation

Navigation markup exists once in:

`partials/navigation.html`

Each page has a simple identifier on `body`, for example:

```html
<body data-page="kunden">
```

`src/app.js` only applies `uk-active` and `aria-current="page"` to the matching navigation item. It does not create the navigation HTML.

## 4. Styling

Use the narrowest correct layer:

- UIkit/global token → `src/themes/harika/`
- shell/sidebar/workspace → `src/styles/shell.less`
- product-specific layout → `src/styles/product.less`
- charts → `src/styles/visualizations.less`
- styleguide-only → `src/styles/prototype.less`

Do not override standard UIkit components in product/shell CSS when a UIkit variable/hook can express the change.

## 5. Partial include mechanism

The include syntax is intentionally tiny:

```html
<!-- @include partials/footer.html -->
```

or with text variables:

```html
<!-- @include partials/workspace-header.html {"title":"Ads","description":"Laufen meine Kampagnen effizient?"} -->
```

Vite expands the partials only for development/build output. No new runtime dependency and no page markup is generated by browser JavaScript.

Nested includes are supported so Sidebar and Mobile Navigation can reuse the same Brand, User and Navigation partials.

## 6. Practical rule

If you want to visually change **one page**, start in that page's HTML.

If you want to visually change **every page**, first check `partials/` or `src/themes/harika/` before touching individual pages.

## Theme level

Before editing styling, decide which inheritance level owns the change:

| Change | Level / file |
| --- | --- |
| UIkit default behavior/reference | Standard — do not customize |
| Harika application appearance | `src/themes/harika/` |
| One customer's branding | `src/themes/customers/<slug>/variables.less` |
| Harika shell/layout | `src/styles/shell.less` |
| Harika product-specific composition | `src/styles/product.less` |

Do not solve a customer branding requirement in the Harika theme. Do not solve a Harika requirement in a customer theme.
